# Fase 1 · Brainstorm

Objetivo: sair daqui com três coisas que a pessoa reconhece e confirma. Nada de código antes disso.

1. **Objetivo:** o que muda no mundo quando isso estiver pronto, e para quem.
2. **Critério de pronto:** como saber que terminou (o que dá para ver, clicar, medir ou rodar).
3. **Restrições:** o que não pode mudar, prazo, tecnologia, orçamento, o que é proibido, se pode commitar.

## Como perguntar

- **Uma pergunta por mensagem.** Nunca uma lista de perguntas.
- Antes da primeira pergunta, leia o contexto em silêncio (README, `CLAUDE.md`, `plan.md`, `git log -15`,
  estrutura de pastas). Não pergunte o que o repositório já responde.
- Prefira múltipla escolha com uma opção recomendada (use a ferramenta de pergunta com opções, se existir).
  Pergunta aberta só quando não dá para prever as respostas.
- Comece pelo propósito ("para que isso serve?"), não pela tecnologia.
- Pare de perguntar assim que os três itens estiverem claros. Normalmente 2 a 5 perguntas bastam.
- Se a pessoa disser "decide você", decida pelo padrão mais comum, diga qual escolheu e siga.

Perguntas que costumam faltar:

- "Quem vai usar e em qual aparelho (computador, celular)?"
- "O que fica fora desta entrega?"
- "Posso fazer commit no fim? Em qual branch?"
- "Existe uma tela ou componente parecido que já está aprovado para eu copiar o comportamento?"

## Devolver o entendimento

Feche com um resumo curto e peça confirmação:

```
Entendi assim:
- Objetivo: ...
- Pronto quando: ... (lista verificável)
- Restrições: ...
- Suposições minhas (corrija se errado): ...
Confirma?
```

Separe o que a pessoa disse do que você supôs. Com o "confirmo", siga para a fase 2. Se o objetivo for grande
demais para uma entrega (vários sistemas independentes), proponha dividir e comece pela primeira parte.
